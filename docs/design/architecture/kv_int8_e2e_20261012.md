# INT8 KV engine qualification, 2026-10-12

Status: **experimental; end-to-end performance has not passed**. This record
separates allocation correctness, actual native execution and latency evidence.
It does not close the 43-item coverage inventory or establish task quality.

## Workload and reference

The bounded serving workload uses the 27B NVFP4 target on four V100 SXM2 32 GB
GPUs, TP4, CUDA 12.8.93, Torch 2.10.0+cu128, driver 580.178.04, FP16 compute,
FP16 draft, seven probabilistic DFlash2 proposals, prefix caching and full CUDA
Graphs. Maximum context is **262144 tokens of capacity**, not an input filled
to that length. Actual inputs are 4096 and 32768 tokens; batched-token capacity
is 8192, maximum sequences four, memory utilization 0.8, attention and Mamba
logical blocks 2048, Mamba align mode, temperature 1.0/top-p 0.95/top-k 20/seed
zero. Each input length has one cold request and three prefix-hit requests,
each bounded at 256 emitted tokens. This latency corpus is not a task-quality
corpus; its length termination does not establish natural EOS health.

The independently initialized FP8 control uses 192 calibrated Q/K/V scalars
from the frozen FP16 4K/8K/32K calibration run. Reference scale fingerprint:
`42d1348f8fb0f2e75c4c63c3135bc9ae3cecbdb0d9a87121b5a833265f8d3cb1`.
Latency corpus fingerprint:
`988bafa7c5145c8f014f172cf5c6d3749be089d12cde16cdbec2788d64eb267d`.
The INT8 token/head encoder computes its own dynamic scales; loading checkpoint

Control and original candidate use source `c75f5b2a83`; the allocation candidate

## Exact physical-page accounting

INT8 scale regions are aligned once per physical page. Multiplying the aligned
one-token size by the block size overstates that page: for a D256 one-head
2048-token ordinary INT8 cache, the old estimate was 1114112 bytes while the
actual view occupies 1064960 bytes. A mismatched Mamba padding estimate then
forced the hybrid planner to a 2097152-byte common page and prevented compact
FP16 draft pages.

The platform now evaluates actual `AttentionSpec` copies at each candidate
block size, preserving kernel/chunk/DCP alignment. The shared compact-page
planner handles a non-integral byte ratio using a compatible divisor of the
existing logical block grid, then pads to the target's physical page. Tensor
precision, model admission and mathematical representation are unchanged.

Twenty-six focused alignment/compact-page checks passed. Three new INT8
alignment cases failed on the parent; the corresponding six FP16/FP8 cases
passed. Actual serving snapshots confirm:

| Cache | Original INT8 | Exact-page INT8 | FP8 control |
| --- | ---: | ---: | ---: |
| Physical page bytes | 2097152 | 1064960 | 1048576 |
| Attention block tokens | 2048 | 2048 | 2048 |
| Draft block tokens | 2048 | 1024 | 1024 |
| Mamba block tokens | 2048 | 2048 | 2048 |

All four ranks retain FP16 convolution and FP32 recurrent state. The page fix
repairs allocation and compact draft geometry; measured latency did not improve.

## Actual graph-node evidence

The optional context observer combines the existing route observer with CPU
NVTX ranges. `analyze_dflash2_context_nodes.py` attributes kernels using CUDA
launch correlation plus the encoded global process ID, then checks the CPU
stage ranges and recorded request/round ordinals. It does not classify kernels
by a guessed GPU time window or equate graph API duration with GPU wall time.

The original INT8 capture correlates all 42584 kernel records. After dropping
both transition rounds, ten rounds on four ranks contain 35480 selected
kernels, including 33160 actual graph nodes, and emit 22 tokens. The target
verifier executes `flash_attention_grouped_verify_e4m3_full_q8_kernel` with
**codec template parameter 3 and row-scale/FP32 specialization**. Its historical
E4M3 name is not evidence of an FP8 cache or a silent scalar fallback.

In this instrumented interval, mean service per rank/round is 13.969 ms in the
target graph, 9.087 ms in draft, 1.529 ms in sample/state and 0.050 ms in target
setup/state. Grouped target attention contributes 2.408 ms. These sums are not
an additive wall-clock latency decomposition: streams can overlap and resident
TP reductions can include cross-rank wait. Profiling perturbs the complete
request substantially, so absolute profiled request throughput is excluded
from performance acceptance. A matched FP8 trace is collected separately.

The matched FP8 trace checks all 192 target scale values against the calibrated
control and correlates all 42944 kernels. Its ten selected rounds contain
35840 kernels/33160 graph nodes and emit 21 tokens; the common target graph
and round geometry are unchanged. Grouped attention service is 1.915 ms per
rank/round versus 2.408 ms for INT8, including approximately 0.222 ms of the
same combine kernel in each. The roughly 0.493-ms main-kernel difference is
consistent with the unprofiled round-cost gap and identifies a useful tuning
target. Draft/TP resident-wait service varies substantially under profiling
and is not promoted as an independent communication regression. These traces
are not the alternating unprofiled performance or task-quality gate.

## Outstanding gates

The shared writer/scorer/indexer stages, allocation checks and successful
requests establish bounded implementation evidence. Remaining qualification
includes missing FP8-reachable fast bindings, engine state/offload/transfer,
multi-seed scored output quality, target-only benefit controls, representative
QSA/MLA engines, matching 35B-A3B AWQ/FP8 pure-decode baselines, clean complete
packages and non-regressing repeated end-to-end latency. None is closed by
this page fix or a route counter.
